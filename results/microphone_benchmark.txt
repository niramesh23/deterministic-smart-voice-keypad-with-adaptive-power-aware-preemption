6. WINDOWS SCHEDULING & PYTHON CALLBACK LIMITATIONS
--------------------------------------------------------------------------------
A. Windows Non-RTOS Pre-emption:
   Windows is a general-purpose operating system. Default thread scheduling quantum is
   approximately 15.625 ms (or 1.0 ms with high-resolution timer requests). High system load,
   Deferred Procedure Calls (DPCs), or Windows background services can cause transient thread delays.

B. Python Global Interpreter Lock (GIL):
   PortAudio invokes the Python callback from an unmanaged native C thread, acquiring the GIL
   via PyGILState_Ensure. If another Python thread is executing a long-running CPU-bound bytecode
   instruction, the callback may experience latency jitter before gaining GIL ownership.
   Mitigation: The callback performs strictly O(1) memory copy and non-blocking queue push,
   leaving all DSP, feature extraction, and ML inference to downstream consumer threads.
